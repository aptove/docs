## What is the bridge?

The bridge is a small, self-contained binary that runs on any machine where your AI agent lives — your laptop, a home server, or a cloud VM. It does three things:

- **Launches your agent** as a child process and pipes ACP messages over stdin/stdout.
- **Exposes a WebSocket server** so the Aptove mobile app can connect and exchange messages.
- **Manages transports** so you can reach the bridge whether you're on the same Wi-Fi network or on the other side of the world.

## Architecture

```
┌─────────────────────────────────────────────────┐
│                  aptove-bridge                   │
│                                                  │
│   WebSocket server ◄──── Transport layer         │
│          │                (local / Tailscale)    │
│          ▼                                       │
│     Agent process (stdio ACP)                    │
└─────────────────────────────────────────────────┘
```

## Installation

### Pre-built binary

Download the latest release for your platform from the [GitHub releases page](https://github.com/aptove/bridge/releases).

### Build from source

```bash
git clone https://github.com/aptove/bridge
cd bridge
cargo build --release
# binary is at target/release/bridge
```

## First run

Running `bridge` with no arguments starts the interactive TUI. On first launch, the setup wizard appears and walks you through:

1. Choosing an agent command (e.g. `copilot --acp`)
2. Picking a transport (local or Tailscale)
3. Configuring any transport-specific credentials

After setup, the bridge starts and immediately shows a QR code for pairing your phone.

## Running from a folder

The bridge is folder-aware. Every time you run `bridge` it looks for (or creates) a `.aptove-bridge/` directory **in the current working directory**. All configuration, credentials, and certificates for that instance live there.

```
~/projects/
  work-agent/
    .aptove-bridge/      ← config for this bridge instance
      common.toml
      cert.pem / key.pem
  personal-agent/
    .aptove-bridge/      ← separate config, separate identity
      common.toml
      cert.pem / key.pem
```

You can also point the bridge at a specific config directory with the `--config-dir` flag:

```bash
bridge --config-dir ~/my-configs/work
```

## Multiple instances on the same machine

You can run as many bridge instances as you like simultaneously — one per folder — and they will operate completely independently:

- Each instance has its own agent identity (`agentId`), auth token, and TLS certificate.
- Each appears as a separate agent entry in the Aptove mobile app.
- Only one bridge instance may run from the same folder at a time (enforced by a per-folder lock file).

Each bridge needs a unique TCP port. By default all instances try port **8765**. If that port is already taken, the bridge automatically finds the next free port in the range 8765–8815, saves it to `common.toml`, and starts normally. See the [Local Transport](/bridge/local-transport#port-conflict-resolution) docs for details.

## Configuration file

All settings are stored in `common.toml` inside the `.aptove-bridge/` directory created wherever you ran the bridge. See [Configuration](/bridge/configuration) for the full reference.
