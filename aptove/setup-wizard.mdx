The first time you run `aptove`, a setup wizard guides you through the minimum configuration needed to start. The wizard also re-runs any time required configuration is missing (for example, if you delete `common.toml`).

---

## Wizard steps

### Step 1 — Choose an AI agent

Aptove Router asks which AI agent to use. You can:

- Select a **preset** (Claude Code, GitHub Copilot, Gemini, Goose) — this fills in the command automatically.
- Choose **Custom** and enter any command that starts an ACP-compatible agent.

The command is saved to `common.toml` as `agent_command`. Aptove Router does **not** test the command at this point — the agent process starts when the mobile app first connects.

<Warning>
If you enter an incorrect command here (wrong executable name, wrong flags), Aptove Router will still start and pairing will still succeed. The mobile app will show an **orange warning triangle** next to the agent name instead of the normal green dot. See [Agent Connection States](/aptove/agent-status) for how to diagnose and fix this.
</Warning>

### Step 2 — Choose a transport

Select how the mobile app connects to Aptove Router:

| Transport | Use case |
|-----------|----------|
| **Local** | Phone and computer on the same Wi-Fi network |
| **Tailscale** | Phone and computer on the same Tailscale network |
| **Cloudflare** *(enterprise)* | Anywhere, via a Cloudflare tunnel |

Each transport requires its own configuration. For Local, no extra config is needed. For Tailscale, you need Tailscale running on both devices. For Cloudflare, you need a Cloudflare Access service token.

### Step 3 — QR code

After the wizard finishes, Aptove Router starts and immediately shows the QR pairing code. Open the Aptove app on your phone, tap **Add agent**, and scan the code.

---

## What happens after pairing

When you scan the QR code:

1. The mobile app establishes a WebSocket connection to Aptove Router.
2. If the AI agent command is valid, the agent process starts and the agent appears in the app with a **green dot** (fully connected).
3. If the AI agent command is invalid (executable not found, wrong flags), the agent still appears in the app but with an **orange warning triangle** — the transport works but the AI is offline.

In case 3, you do not need to re-pair. Use the `/agent` slash command in Aptove Router to correct the command:

```
/agent
```

The app will reconnect and the warning will clear automatically once the agent process starts successfully.

---

## Re-running the wizard

The wizard re-runs automatically when required config is missing. You can also trigger individual wizard steps while Aptove Router is running:

| Slash command | Opens wizard step for |
|---------------|-----------------------|
| `/agent` | AI agent command |
| `/transport` | Transport selection |

---

## Configuration file

The wizard writes your choices to `common.toml` in the `.aptove/` directory (created in whichever directory you ran `aptove` from). You can edit this file directly — changes take effect on the next start.

See [Configuration](/aptove/configuration) for the full list of fields.
