---
title: "Agent Name"
description: "How Aptove Router determines the agent's display name and how to rename it from iOS or common.toml."
---

The agent name is the user-visible label shown in push notification titles and in the iOS app's agent list. This page explains where the name comes from, how to change it, and how the bridge and iOS stay in sync.

---

## Where the name comes from

When Aptove Router starts for the first time (no `agent_name` in `common.toml`), it derives a default from the **folder name** of the working directory:

```
$ cd ~/code/my-project
$ aptove
# → agent_name = "my-project" written to .aptove/common.toml
```

This default is immediately persisted to `common.toml` so subsequent restarts use the same value without re-deriving it.

| Config key | Type | Default |
|------------|------|---------|
| `agent_name` | `string` (optional) | Folder name on first run |

---

## How to set it manually

Edit `.aptove/common.toml` directly:

```toml
agent_name = "My Work Assistant"
```

Restart Aptove Router — the new name takes effect immediately and will appear in subsequent push notification titles.

---

## Mobile sync

The iOS app can rename the agent via **Agent Settings → Edit Name**. When the user saves a new name:

1. CoreData is updated locally (the iOS app's display name changes immediately).
2. The iOS app sends `bridge/setAgentName` to Aptove Router.
3. Aptove Router updates its in-memory name (used for push notifications) and persists `agent_name` to `common.toml`.

This means a name set on iOS survives a bridge restart — it is written to disk.

---

## `bridge/identify` now includes `agentName`

On every connection, before any ACP messages are exchanged, Aptove Router sends `bridge/identify`. This notification now includes `agentName`:

```json
{
  "jsonrpc": "2.0",
  "method": "bridge/identify",
  "params": {
    "bridgeAgentId": "3f2a1b4c-...",
    "cwd": "/Users/alice/code/my-project",
    "agentName": "my-project"
  }
}
```

iOS receives this and syncs the name to CoreData on every connect, so the app always reflects the bridge's current configured name.

---

## Protocol reference

### `bridge/setAgentName` (client → bridge)

Sent by the iOS app when the user renames the agent in settings. Aptove Router intercepts this message — it is **never forwarded to the agent process**.

```json
{
  "jsonrpc": "2.0",
  "method": "bridge/setAgentName",
  "params": {
    "name": "My Work Assistant"
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | New user-visible name for this agent instance |

No response is sent — this is a one-way notification.

---

## Conflict resolution

If the iOS app has a local rename that has not yet been synced to the bridge (e.g., the bridge was offline when the rename happened), the following logic applies on the next connection:

1. Bridge sends `bridge/identify` with its configured `agentName`.
2. iOS compares it to the locally stored name.
3. If they differ, iOS **wins** — it immediately sends `bridge/setAgentName` with the local name, updating the bridge and `common.toml`.
4. If they are the same (or if iOS has no local name), the bridge's name is accepted as-is.

This ensures that an iOS-initiated rename always propagates to the bridge, even after a period of being offline.

---

## Multiple devices

When multiple iOS devices are connected to the same bridge:

- All devices receive `agentName` via `bridge/identify` on connect and sync to CoreData.
- If one device renames the agent, it sends `bridge/setAgentName` → bridge persists the new name → the other devices will see the new name on their next connection.
- Real-time broadcast to already-connected devices is not implemented; they see the new name on reconnect.
