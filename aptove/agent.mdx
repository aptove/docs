## What to enter

When Aptove Router asks for an agent command, enter the command that starts your AI agent. The command must launch a process that speaks the [Agent Client Protocol](https://agentclientprotocol.com) over **stdio** (stdin / stdout).

Aptove Router will spawn this command as a subprocess and relay messages between it and the Aptove mobile app.

### Command parsing rules

The command is **not** run through a shell. Aptove Router splits it using POSIX-style word splitting (shlex), then spawns the program directly. This means:

| Feature | Supported |
|---------|-----------|
| Single and double quotes (for arguments with spaces) | ✓ yes |
| `~` home directory expansion | ✗ no — use the full path |
| `$VARIABLE` environment variable expansion | ✗ no — expand variables in the value before saving |
| Pipes (`\|`), `&&`, `;` chaining | ✗ no — only a single command |

**Example with a quoted argument:**
```
my-agent --model "gpt-4o" --prompt "run in silent mode"
```

If the executable is not on `$PATH`, use the full absolute path:
```
/usr/local/bin/my-agent --acp
```

## Working directory

Aptove Router spawns the agent process with its working directory set to **the directory where `aptove` was launched**. The agent inherits that directory as its `cwd`.

This matters for agents that use the working directory as project context (such as Claude Code or GitHub Copilot CLI). Run `aptove` from the root of the project you want the agent to work on:

```bash
cd ~/projects/my-app
aptove
```

The agent will then treat `~/projects/my-app` as its working directory, so file edits, searches, and shell commands will be relative to that path.

<Note>
If you move or rename the directory after Aptove Router starts, the agent's working directory does not update automatically. Restart `aptove` from the new location.
</Note>

## Available agents

### GitHub Copilot

Requires the [GitHub Copilot CLI extension](https://docs.github.com/en/copilot/using-github-copilot/using-github-copilot-in-the-command-line).

```
copilot --acp
```

#### Yolo mode

Yolo mode skips confirmation prompts, letting Copilot execute tool calls automatically without asking each time.

<Warning>
`--yolo` removes all human confirmation steps. The agent can read and write files, run shell commands, and make API calls without prompting. Only use this mode on a machine where you are comfortable with autonomous execution — ideally inside a sandboxed environment such as a Docker container or a dedicated virtual machine, not on your primary workstation.
</Warning>

```
copilot --acp --yolo
```

### Google Gemini

Requires the [Gemini CLI](https://github.com/google-gemini/gemini-cli).

```
gemini --experimental-acp
```

### Goose AI

Requires [Goose](https://github.com/block/goose).

```
goose acp
```

### OpenAI Codex (via codex-acp)

Requires Node.js. Runs the ACP wrapper for OpenAI Codex CLI.

```bash
npm install -g @agentclientprotocol/codex-acp@2.6.0
codex-acp
```

<Note>
To upgrade to a newer version, re-run the install command with the updated version tag, or omit `@2.6.0` to install the latest.
</Note>

### Claude (via claude-code-acp) {#claude-via-claude-agent-acp}

Requires Node.js and a [Claude Code](https://claude.ai/download) installation. Install the package globally, then use the `claude-code-acp` command:

```bash
npm install -g @agentclientprotocol/claude-agent-acp@0.101.0
```

```
claude-code-acp
```

<Note>
To upgrade to a newer version, re-run the install command with the updated version tag, or omit `@0.101.0` to install the latest.
</Note>

#### Authentication

`claude-code-acp` uses your Claude Code session — no separate API key is needed. Before using it with Aptove, make sure you are logged in:

1. Open a terminal and run `claude`
2. Type `/login` and complete the browser-based login flow

If you see this error in the Aptove log panel:

```
ERROR 🔐 Agent returned authentication error — check API key / agent auth config
```

Your session has expired. Re-run `claude` → `/login` to refresh it, then use `/agent` in Aptove to reload the agent without restarting.


#### Yolo mode

Yolo mode skips all permission prompts, letting Claude run shell commands and edit files without asking for confirmation.

<Warning>
`--dangerously-skip-permissions` removes all human confirmation steps. Claude can execute arbitrary shell commands, modify files, and perform tool calls without prompting. Only use this mode on a machine you control and are comfortable with autonomous execution — ideally inside a sandboxed environment such as a Docker container or a dedicated virtual machine, not on your primary workstation with broad filesystem access.
</Warning>

```
claude-code-acp --dangerously-skip-permissions
```

### Custom / other agents

Any process that implements the ACP stdio protocol can be used. Enter the full shell command including arguments:

```
my-agent --acp --model gpt-4
```

## Process lifecycle

Aptove Router starts the agent command as a managed subprocess and terminates it when the session ends or Aptove Router exits. If Aptove Router crashes or is killed hard (`kill -9`), the agent subprocess may be left running. To clean up orphaned processes:

```bash
# Find and kill a stale claude-agent-acp process
pkill -f "claude-agent-acp"
# Or for Copilot
pkill -f "copilot --acp"
```

Running agents in a container avoids this entirely — the container's process group is cleaned up automatically when the container stops.

## Mobile app authentication warnings

When the mobile app connects to an agent that advertises authentication status support, it automatically checks whether the agent's session is still valid. If the session has expired or the agent requires re-authentication, the app surfaces this in two places:

- **Agent list** — an orange warning badge replaces the green status dot next to the agent name.
- **Chat** — an orange banner appears at the top of the conversation: *"Authentication Required — This agent requires authentication. Please sign in on your computer."*

To resolve the warning, re-authenticate on the computer running Aptove Router (the exact steps depend on the agent — for Claude, run `claude` → `/login`), then reconnect from the mobile app. The warning clears automatically once the app establishes a new connection and confirms the session is valid.

Agents that do not implement the `auth/status` ACP capability are unaffected — no badge or banner is shown for them.

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `Failed to start 'copilot --acp'` | Agent is not installed or not on `$PATH` |
| Agent starts but Aptove Router shows no clients | Agent is not in ACP mode — add the required flag (e.g. `--acp`) |
| Agent exits immediately | Run the command manually in a terminal to see the error output |
| `ERROR 🔐 Agent returned authentication error` (Claude) | Claude Code session expired — run `claude` → `/login`, then use `/agent` in Aptove to reload |
| Orange warning badge / banner in the mobile app (auth) | Agent session expired — re-authenticate on the computer and reconnect from the mobile app |
| Orange warning badge in the mobile app — "AI agent offline" | The command was saved but the executable failed to spawn. Use `/agent` in Aptove Router to correct the command. See [Agent Connection States](/mobile-app/connection-states) for the full state model. |
